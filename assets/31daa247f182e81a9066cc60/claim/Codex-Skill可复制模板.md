# Codex Skill 提炼与创建模板

> 用途：把已经反复执行、输入输出相对稳定的任务，沉淀成可重复调用的 Skill。请先提炼和确认流程，再创建文件。

## 1. Skill 提炼提示词

请复盘你当前能够访问的最近会话、当前项目文件和任务记录，找出我反复手动执行的任务。不要假设你能看到未提供或无权访问的历史；如果材料不足，先告诉我还需要哪些记录。

先列出候选流程，并按以下六项分别用 1-5 分评估：出现频率、流程稳定性、输入是否明确、输出是否可验收、预计节省时间、出错风险。然后选出最适合沉淀成 Skill 的 3 个流程。

每个流程写清楚：

1. Skill 名称建议
2. 适用场景和触发语句
3. 必需输入材料
4. 前置条件
5. 执行步骤和关键判断
6. 输出结果和保存位置
7. 质量检查与验收标准
8. 异常情况、停止条件和需要我确认的动作
9. 涉及的隐私、权限或合规边界

先输出分析和推荐，不要立即创建或安装 Skill。等我确认其中一个流程后，再继续生成 Skill 文件。

## 2. 把确认流程生成 Skill 的提示词

把我确认的第【X】个流程制作成一个 Codex Skill。Skill 名称使用小写字母、数字和连字符，保持简短。`SKILL.md` 的 YAML frontmatter 只保留 `name` 和 `description`；`description` 同时写清楚它做什么，以及哪些用户表达或任务场景应该触发它。

正文使用简洁的命令式说明，只保留 Codex 真正需要的流程知识。写清输入、步骤、输出、验收、异常处理、停止条件和授权边界。详细行业规则放进 `references/`，确定性强且会反复执行的动作才考虑写进 `scripts/`，不要创建无关的 README、安装说明或变更日志。

先给我看文件结构和 `SKILL.md` 草稿，等我确认后再创建文件。创建完成后运行 Skill 校验，并用一个真实小任务测试输出是否符合验收标准。

## 4. 金融行业三个常用方向

### 行业资料整理 Skill

- 输入：行业范围、时间范围、资料来源、输出用途。
- 输出：关键事实、来源与日期、争议点、待核实项、结构化摘要。
- 边界：不编造实时数据；需要最新信息时使用可访问的权威来源；不把资料整理写成投资建议。

### 市场信息复盘 Skill

- 输入：市场范围、复盘周期、指定资料和关注维度。
- 输出：已确认事实、主要变化、可能影响因素、不同观点、下一步核实清单。
- 边界：事实与推断分开；标注数据时间；禁止无证据预测收益或价格。

### 客户沟通整理 Skill

- 输入：授权的沟通记录、客户背景、产品资料、合规话术。
- 输出：客户需求、关注点、异议、承诺事项、跟进任务和待确认信息。
- 边界：隐藏身份证号、手机号、账号等个人信息；不自动发送消息；不替客户做投资决策。

## 5. 调用方式

完成并安装后，可以在任务中直接说：

> 请按【Skill 名称】处理这批材料。先检查输入是否完整，缺少关键材料就告诉我；完成后按 Skill 规定的格式交付并运行验收检查。

## 6. 判断一个流程是否值得做成 Skill

- 至少重复出现过 3 次。
- 每次输入和步骤大体相似。
- 输出格式可以说清楚。
- 有明确的检查标准。
- 沉淀后能减少重复解释或返工。
- 风险可以通过停止条件和人工确认控制。

如果任务每次差异很大、只做一次、没有固定输出，或者完全依赖临场判断，先不要做成 Skill。
